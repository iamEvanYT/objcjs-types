# Typed Block Wrappers

## Overview

Generate per-method block wrapper functions that encapsulate Objective-C type encodings,
so users don't need to manually specify block signatures when calling methods that accept
block parameters.

## Motivation

When Objective-C methods only expose `@?` for block parameters (without extended type
encodings), objc-js falls back to heuristics. The `typedBlock()` function allows users
to provide explicit signatures, but it requires manually specifying the encoding:

```typescript
// Current: user must know the encoding
import { typedBlock } from "objc-js";

arr.enumerateObjectsUsingBlock$(
  typedBlock({ returns: "v", args: ["@", "Q", "^B"] }, (obj, idx, stop) => {
    console.log(obj.toString(), idx);
  })
);
```

This is error-prone and requires users to understand ObjC type encodings.

## Solution

Generate one block wrapper function per method that accepts a block parameter. Each
wrapper embeds the correct encoding internally:

```typescript
// New: type-safe, encoding handled for you
import { enumerateObjectsUsingBlock$Block } from "objcjs-types/Foundation/blocks";

arr.enumerateObjectsUsingBlock$(
  enumerateObjectsUsingBlock$Block((obj, idx, stop) => {
    console.log(obj.toString(), idx);
  })
);
```

## Design Goals

1. **Type-safe**: TypeScript ensures the callback has the correct signature
2. **Tree-shakable**: One export per method, bundlers remove unused wrappers
3. **Zero runtime overhead**: Just a thin wrapper around `typedBlock()`
4. **No user knowledge of encodings**: The encoding is embedded in the wrapper

## Generated Output

Each framework gets a `blocks.ts` file:

```typescript
// AUTO-GENERATED by objcjs-types generator — DO NOT EDIT
import { typedBlock } from "objc-js";
import type { NobjcObject } from "objc-js";

/**
 * Block wrapper for NSArray.enumerateObjectsUsingBlock:
 * @param fn Callback receiving (obj, idx, stop)
 */
export function enumerateObjectsUsingBlock$Block(
  fn: (obj: NobjcObject, idx: number, stop: NobjcObject) => void
): (obj: NobjcObject, idx: number, stop: NobjcObject) => void {
  return typedBlock("@?<v@?@Q^B>", fn);
}

/**
 * Block wrapper for NSArray.sortedArrayUsingComparator:
 * @param fn Callback receiving (obj1, obj2) and returning comparison result
 */
export function sortedArrayUsingComparator$Block(
  fn: (arg0: NobjcObject, arg1: NobjcObject) => number
): (arg0: NobjcObject, arg1: NobjcObject) => number {
  return typedBlock("@?<q@?@@>", fn);
}
```

## Block Encoding Format

The full block encoding uses angle brackets: `@?<returnType@?argTypes...>`

- `@?` prefix indicates a block type
- Return type comes first
- `@?` for implicit block-self parameter
- Then each argument's encoding

Examples:
| ObjC Block Type | Full Encoding |
|----------------|---------------|
| `void (^)(id, NSUInteger, BOOL *)` | `@?<v@?@Q^B>` |
| `NSComparisonResult (^)(id, id)` | `@?<q@?@@>` |
| `void (^)(id)` | `@?<v@?@>` |
| `void (^)(void)` | `@?<v@?>` |
| `BOOL (^)(id, id)` | `@?<B@?@@>` |

## Implementation

### Files to Modify

| File                       | Change                              |
| -------------------------- | ----------------------------------- |
| `generator/type-mapper.ts` | Add `blockQualTypeToFullEncoding()` |
| `generator/emitter.ts`     | Add `emitBlocksFile()`              |
| `generator/index.ts`       | Call emitter and write blocks.ts    |
| `package.json`             | Add `./*/blocks` export             |

### type-mapper.ts

New export:

```typescript
/**
 * Convert a block qualType to its full ObjC type encoding with angle brackets.
 * e.g., "void (^)(id, NSUInteger, BOOL *)" → "@?<v@?@Q^B>"
 */
export function blockQualTypeToFullEncoding(qualType: string): string | null;
```

Uses existing `qualTypeToEncoding()` for individual types.

### emitter.ts

New function:

```typescript
/**
 * Generate a blocks.ts file for a framework containing typed wrappers
 * around `typedBlock()` from objc-js.
 *
 * Returns null if no block parameters are found in the framework.
 */
export function emitBlocksFile(
  classes: ObjCClass[],
  protocols: ObjCProtocol[],
  currentFramework: FrameworkConfig,
  allFrameworks: FrameworkConfig[],
  classToFile?: Map<string, string>
): string | null;
```

Logic:

1. Iterate all methods in all classes and protocols
2. For each parameter with block type (`(^)`):
   - Generate wrapper function named `{selector}Block`
   - For methods with multiple blocks: `{selector}Block0`, `{selector}Block1`
3. Deduplicate: same selector + same encoding = one wrapper
4. Sort alphabetically for deterministic output

### index.ts

After emitting class files for each framework:

```typescript
const blocksContent = emitBlocksFile(classes, protocols, framework, allFrameworks, classToFile);
if (blocksContent) {
  await writeFile(join(frameworkDir, "blocks.ts"), blocksContent);
}
```

### package.json

Add export:

```json
"./*/blocks": {
  "types": "./dist/*/blocks.d.ts",
  "default": "./dist/*/blocks.js"
}
```

## Edge Cases

### Methods with Multiple Block Parameters

Rare but possible. Use numeric suffix:

```typescript
export function someMethod$Block0(fn: ...) { ... }
export function someMethod$Block1(fn: ...) { ... }
```

### Same Selector in Multiple Classes

One wrapper works for all classes if the encoding is identical. If encodings differ
(unlikely), emit separate wrappers with class prefix.

### Block Returns Non-Void

Handle in encoding and TypeScript type:

```typescript
export function sortedArrayUsingComparator$Block(
  fn: (a: NobjcObject, b: NobjcObject) => number
): (a: NobjcObject, b: NobjcObject) => number {
  return typedBlock("@?<q@?@@>", fn);
}
```

### Nested Blocks

Block parameters that themselves take blocks. The encoding handles this recursively.
TypeScript type is already generated correctly by existing `parseBlockType()`.
